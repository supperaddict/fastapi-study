# 从 Python 语法到 FastAPI 后端：完整学习回顾

这份笔记对应本仓库的实际代码。最初的目标是用约90小时了解 API 后端、数据库、缓存、认证、测试和部署。学习中大部分代码通过复制后运行验证，因此目前更适合定位为“看过并跑过完整流程”，而不是“已经能独立实现”。接下来用真实平台任务拆成小功能练习，不必先把整个后端知识体系背完。

## 1. 先建立一个完整画面

```text
浏览器 / App / 其他服务
        ↓ HTTP 请求
Uvicorn 接收请求
        ↓
FastAPI 按方法+路径匹配路由
        ↓
Pydantic 校验输入 + Depends 执行依赖
        ↓
接口函数：权限与业务逻辑
        ├── SQLAlchemy Session → PostgreSQL
        ├── Redis 缓存
        └── HTTPX → 外部服务
        ↓
响应模型过滤/校验 → JSON + 状态码
```

Uvicorn 是 ASGI 服务器；FastAPI 是定义接口、处理参数和组织请求逻辑的框架。PostgreSQL 是正式数据来源；Redis 只缓存可以重新构建的数据。

### 项目启动命令

```bash
source .venv/bin/activate
python -m uvicorn main:app --reload --port 8001
```

- `python -m uvicorn`：使用当前 Python 环境运行 Uvicorn。
- `main:app`：加载 `main.py` 中的 `app` 对象。
- `--reload`：开发时保存代码后重载，生产环境不使用。
- `--port 8001`：监听8001端口。
- 新终端通常要重新激活虚拟环境。Docker 命令不依赖 Python 虚拟环境。

## 2. 路由、方法和参数

`@app.get('/health')` 规定 GET /health 执行哪个函数。路由由“方法+路径”共同确定；GET /users 与 POST /users 是不同接口。拆分文件后用 `APIRouter(prefix='/users')` 组织，再通过 `app.include_router()` 注册。

| 类型 | 示例 | 用途 |
|---|---|---|
| 路径参数 | `/users/3` 中的3 | 选定资源 |
| 查询参数 | `/users?page=2&size=10` | 筛选、分页 |
| 请求体 | POST 中的 JSON | 创建、修改数据 |
| 请求头 | Authorization | 携带认证和元信息 |

URL 中 `?` 表示查询参数开始，`=` 连接名称和值，`&` 分隔多个参数。这是 URL 语法，不需要在 Python 里“定义问号”。

GET 通常读取；POST 通常创建或执行操作；PATCH 局部修改；DELETE 删除。浏览器地址栏直接访问通常发 GET，不能用它代替 POST/PATCH/DELETE 测试。POST 不自动加密，传输加密由 HTTPS 提供。

## 3. /docs 是真实请求工具

Swagger 文档中的 Try it out → Execute 会真正调用你的应用，不是虚构数据的演示。接数据库后可能真的写入或删除数据。

- Request body：提交给服务器的数据。
- Server response → Code：本次真实状态码。
- Response body：本次真实返回内容。
- 下方 Responses 的示例：可能的响应说明，不代表这次真的失败。

204 没有响应体正常。网页一直转圈时，先看 Uvicorn 终端，确认启动成功，不要只在浏览器反复刷新。

## 4. Pydantic：输入模型与输出模型

`schemas.py` 描述 API 的请求/响应契约，`models.py` 描述数据库表，二者不是一个东西。

```python
class UserCreate(BaseModel):
    username: str = Field(min_length=1, max_length=20)
    age: int = Field(ge=0, le=150)
```

类型声明让 FastAPI 解析、校验数据；失败会在进入业务函数前返回422。`Field` 声明长度、范围等；`Query` 在查询参数上声明校验。`EmailStr` 检查邮箱格式，需要 email-validator，但不证明邮箱真实存在或归用户所有。

### 必填、默认值和 null

| 声明 | 可省略 | 可传 null |
|---|---|---|
| `name: str` | 否 | 否 |
| `name: str = 'guest'` | 是 | 否 |
| `name: str \| None` | 否 | 是 |
| `name: str \| None = None` | 是 | 是 |

局部修改用 `model_dump(exclude_unset=True)` 只取明确提交的字段。没有提交 email 表示不修改；提交 `email: null` 表示清空。用户名、年龄不可清空，邮箱可以清空，所以不能统一拒绝所有 None。

- `model_dump()`：模型转字典。
- `model_dump_json()`：模型转 JSON 字符串。
- `model_validate()`：从输入对象生成模型。
- `ConfigDict(from_attributes=True)`：允许从 ORM 对象属性读取。
- `extra='forbid'`：拒绝多余输入字段，文章接口借此拒绝客户端传 author_id。

输出用 `response_model` 控制结构，密码和哈希从来不进入 UserResponse。

## 5. 状态码与异常

| 码 | 含义 |
|---|---|
| 200 | 正常查询或修改 |
| 201 | 创建成功 |
| 204 | 成功，无响应体 |
| 400 | 当前操作的业务输入不正确，如旧密码错误 |
| 401 | 无有效认证凭证 |
| 403 | 已认证但无权限 |
| 404 | 路由或资源不存在 |
| 405 | 方法不支持 |
| 409 | 数据状态冲突，如用户名重复 |
| 422 | JSON、字段类型或校验不通过 |
| 500 | 未预期服务端错误 |
| 502/504 | 上游服务异常/超时 |

`raise HTTPException(...)` 会中止正常处理并生成错误响应。单纯 `return {'detail': ...}` 通常仍是成功状态，不能代替错误处理。未知异常由 main.py 的处理器返回通用500和请求编号，细节只在服务端日志中查看。

## 6. 拆文件与依赖注入

main.py 负责装配应用，不应该无限堆积业务代码。users.py/auth.py/posts.py 分别组织业务路由；config.py 管配置，database.py 管会话。

`Depends(get_current_user)` 的含义：先执行这个依赖，把返回结果传给参数。传的是函数本身，不是 `Depends(get_current_user())`。

```text
get_session → get_current_user → require_self → 修改用户接口
```

依赖可以有子依赖；同次请求相同依赖通常复用结果。使用 `yield` 的依赖可以在接口完成后清理资源。普通辅助函数不会因为被 async 函数调用就自动进入线程池。

## 7. 从内存字典到数据库

最初 CRUD 使用字典，重载服务就丢数据。数据库将数据持久保存。表是一类记录，行是一条记录，列是字段，主键唯一标识记录。

SQL 基础：

```sql
SELECT id, username FROM users WHERE age >= 18 ORDER BY id LIMIT 10 OFFSET 0;
INSERT INTO users (username, age) VALUES ('demo', 20) RETURNING id;
UPDATE users SET age = 21 WHERE id = 1;
DELETE FROM users WHERE id = 1;
```

UPDATE/DELETE 没有 WHERE 可能作用于所有行。字符串用单引号；语句用分号结束。`\d` 列出表/序列；`\d users` 查看用户表结构；`\q` 退出 psql。users_id_seq 是编号序列，不是错误表。

通过 Python 执行 SQL 使用绑定参数 `:user_id`，不要将用户输入拼接进 SQL。

## 8. ORM 与事务

SQLAlchemy 将 User/Post 类映射到表，实例映射到记录；数据库中仍然执行 SQL。

| 操作 | ORM 写法 |
|---|---|
| 创建 | `session.add(user)` |
| 主键查询 | `session.get(User, id)` |
| 查询列表 | `session.scalars(select(User)).all()` |
| 修改 | `user.age = 21` |
| 删除 | `session.delete(user)` |
| 提交 | `session.commit()` |
| 回滚 | `session.rollback()` |
| 重新读取 | `session.refresh(user)` |

`add` 不等于立即永久保存；commit 会先 flush 待写入变更，再提交事务。refresh 负责读取，不负责保存。提交失败后 rollback 让会话恢复可用。数据库唯一约束是避免重复用户名的最终保障。

`with_for_update=True` 在事务中锁定查询到的行，减少“读→改→写”并发覆盖。它不是所有并发问题的万能解。

`scalars()` 取每行第一个元素：select(User) 时得到 User 对象；多列查询应使用 execute(...).mappings()，否则可能只剩第一列。

## 9. Alembic 管理表结构

修改 models.py 不会自动修改现有表。

```bash
alembic revision --autogenerate -m 'describe change'
# 检查生成文件
alembic upgrade head
alembic current
alembic check
```

upgrade 向前执行变更；downgrade 撤销结构，可能删数据。stamp 只标记版本，不执行建表。项目最初已有表，所以核对后建立初始迁移并 stamp；空数据库则必须 upgrade，不能 stamp 假装建好表。

本仓库迁移按顺序完成：建 users→加 email→加 hashed_password→建 posts→加 auth_version。新增非空字段时考虑历史记录，先允许空或设置合理回填方案。

## 10. 密码与 JWT

密码用 Argon2 哈希保存，不保存明文。相同密码因随机盐通常得到不同哈希，通过 verify 验证，不要“再哈希后比较字符串”。

```text
注册：密码 → 哈希 → PostgreSQL
登录：用户名查用户 → verify → 签发 JWT
请求：Bearer Token → 验签/过期检查 → 查用户 → 权限判断
```

JWT 是签名凭证，不是加密容器，内容可以解码读取。sub 存用户编号，exp 存过期时间，ver 对应用户的 auth_version。服务器固定允许的签名算法，不能相信 Token 自己随意声明的算法。

/auth/login 使用 JSON 请求体；/docs 的 Authorize 只填 Token。本项目使用 HTTPBearer，不是已经实现第三方 OAuth 登录。

认证回答“你是谁”，授权回答“你能做什么”。用户只能改删自己的账号；文章作者必须等于 current_user.id。author_id 由服务器赋值，不能由客户端选择。

改密码先验旧密码，再哈希新密码，并递增 auth_version，旧 Token 从下一次验证开始被拒绝。旧学习版没有版本号，因此改密码后 Token 会一直有效到过期；完善版修复了这个限制。

## 11. 异步、并发与 HTTPX

`async def` 定义协程函数；调用得到协程对象，需要 await 或调度才执行。await 在等待可挂起操作时让出执行机会，但不会自动让所有语句并发。

```python
# 顺序：约4秒
await fetch_a()
await fetch_b()
# 并发：两个各等待2秒的任务，总体约2秒
await asyncio.gather(fetch_a(), fetch_b())
```

time.sleep 会阻塞线程，asyncio.sleep 是异步等待。独立脚本用 asyncio.run(main())；FastAPI 已运行事件循环，异步接口里直接 await，不再 asyncio.run。

同步 Session 和同步 Redis 在普通 def 接口中运行；FastAPI 把普通接口放在线程池。把它们直接改成 async def 不会让数据库自动异步。

HTTPX AsyncClient 发出真实请求；await client.get() 等响应；raise_for_status() 检查状态；response.json() 解析已收到数据，不需要 await。设置超时并捕获请求、状态、JSON错误。HTTPX 的网络超时不是全请求硬性总时长。

## 12. 多表、外键和 N+1

一个用户对应多篇文章，posts.author_id 外键指向 users.id。外键维护数据完整性，删除用户通过 ON DELETE CASCADE 删除文章。本项目先用显式 JOIN，不必为了关联查询强行增加 relationship。

```sql
SELECT posts.title, users.username
FROM posts JOIN users ON posts.author_id = users.id;
```

N+1：先查一次列表，再在循环里逐条查关联记录。10篇文章、10个不同且尚未加载的作者，可能产生11次查询。Session 身份映射会复用部分对象，所以实际不一定严格是N次。显式 JOIN 或合适的 ORM 预加载可避免。数据库查询次数和网络往返往往比 Python 循环本身更重要。

## 13. Redis 缓存

Redis String 可以保存 JSON 文本，`SET key value EX 60` 设置60秒过期。TTL 正数表示剩余时间，-1无过期，-2不存在。decode_responses=True 让 Python 读取字符串。

```text
读缓存 → 命中返回
       → 未命中查 PostgreSQL → 缓存60秒 → 返回
修改/删除：先提交 PostgreSQL → 删除旧缓存
删除用户：记下文章编号 → 删用户/级联删文章 → 清理文章缓存
```

Redis 断线降级到数据库。TTL 是过期兜底，不是强一致性保证：并发请求可能在删除缓存后回填旧版本，失效失败也可能暂存旧数据。要更严格一致需要结合版本、失效事件、事务 outbox 等设计，当前未实现。

三个面试概念：

- 穿透：反复请求不存在的资源，缓存没有就不断打数据库。可以用短暂空值缓存、输入校验，必要时布隆过滤器。本项目未启用空值缓存。
- 击穿：一个热点键失效，很多请求同时回源。可以用单次加载合并、受控互斥或逻辑过期，本项目未实现热点保护。
- 雪崩：很多键同时失效，或整个 Redis 故障，数据库压力骤增。可用过期时间抖动、限流、容量保护与降级；当前只实现降级，不能声称已经防住雪崩。

不要为了缓存而缓存。先确认数据可以短暂陈旧、读取频繁且查询成本值得，当前缓存的是公开文章详情，不缓存登录校验和密码。

## 14. 自动化测试

pytest 执行 test_ 开头函数；TestClient 直接调用 app，不需要 Uvicorn。assert 检查结果，`json=` 提交请求体，`headers=` 传 Token。

fixture 为测试准备资源，yield 后清理。conftest.py 自动发现公共 fixture。dependency_overrides 把正式 get_session/get_cache 换成测试实现。

数据库用独立 *_test 库；每个测试外层事务，Session 使用 create_savepoint，接口正常 commit 后整个测试仍能回滚。编号序列不会回滚，因此不要断言固定编号。缓存用每次新建的 FakeRedis，防止测试数据进入真实 Redis。外部 HTTP 用 MockTransport，不依赖公网是否可用。

```bash
python prepare_test_db.py
python -m pytest -q
ruff check .
ruff format --check .
```

测试不仅看403，还要查询数据确认未修改；缓存测试要先把旧数据读进缓存，再改后查询，否则只测到了数据库更新。完善版还验证了缓存命中不再查主键、账号删除、旧 Token 撤销、Redis 断线降级和无效/过期 Token。

## 15. 配置、日志、部署

config.py 统一读取 .env，随机密钥必须设置。配置示例可以公开，真实 .env 不能提交；数据库数据、备份、虚拟环境也不能提交。

日志使用 JSON 并提供 X-Request-ID，记录方法、路径、状态和耗时；不记录请求体、密码或 Token。先用 /health 确认进程，再用 /ready 确认数据库。

Dockerfile 多阶段构建依赖并使用非 root 用户。Compose 编排 PostgreSQL、Redis、一次性迁移、API，可选 Caddy 反代。数据库保存在命名卷，Redis 缓存可重建。API 默认只发布到宿主机回环地址。真实 HTTPS 依赖域名解析、服务器和80/443端口，提供配置不等于已经上线。

详细命令见[部署说明](部署说明.md)。

## 16. 这次实际遇到的错误

| 现象 | 原因与处理 |
|---|---|
| 全部 Not Found | 可能启动错文件或访问旧服务，确认目录、文件和端口 |
| Method Not Allowed | 添加 DELETE 时覆盖了 GET；同路径不同方法都要保留 |
| 页面一直转圈 | 后端加载失败，先看终端，不要先猜网络 |
| Query 未定义 | 拆文件时漏导入 Query，每个文件独立导入名称 |
| No module named alembic | 新终端没激活环境或依赖装到其他解释器 |
| json_invalid | JSON 语法错误，比如字符串未加双引号 |
| int_parsing | JSON 合法，但 age 不能转换为整数 |
| 邮箱 null 被拒绝 | 仍使用“所有字段不能None”的旧检查，应按字段判断 |
| /docs 没变化 | 依赖重构或数据库迁移不一定改变 API 契约 |
| 看不到表字段 | 执行了反斜杠d而不是反斜杠d users |
| Unable to find image locally | 本地没镜像，会尝试下载；不是最终失败结论 |

## 17. 以后做真实平台时怎么用

不要从“我要再学十个框架”开始，先选一条用户路径，例如“登录后创建任务、查看任务列表”。

1. 写清角色、资源、权限和成功/失败条件。
2. 定义输入输出模型，不急着写全部代码。
3. 设计最少必要的表和约束，生成迁移。
4. 实现一条接口，验证归属检查。
5. 写成功、无权限、输入错误三个测试。
6. 看日志与 SQL，确认理解请求链路。
7. 最后再考虑缓存和异步任务，避免过早增加组件。

建议先独立实现“给文章增加摘要 summary”：自己写模型、迁移、请求响应、局部修改和测试。卡住时只查对应章节，不整段替换所有文件。真正能解释为什么选择 nullable、为什么要 commit、为什么作者来自 Token，比记住完整语法更有价值。
