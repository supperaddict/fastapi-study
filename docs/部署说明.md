# 部署与运维

## 1. 配置与启动

复制 `.env.example` 为 `.env`，生成并设置至少32字符随机 JWT 密钥；生产环境为数据库设置随机字母数字密码。不要提交 `.env`。Compose 内部数据库和 Redis 通过服务名 `db`、`redis` 访问，localhost 指容器自身，不能用于访问其他容器。

```bash
docker compose up --build -d
docker compose ps
docker compose logs --tail=100 api migrate
curl -f http://127.0.0.1:8001/health
curl -f http://127.0.0.1:8001/ready
```

`/health` 只检查进程能响应；`/ready` 检查 PostgreSQL。Redis 可以降级，所以不纳入核心就绪条件。`migrate` 执行后状态为 Exited(0) 正常。

容器使用非 root 用户，不用 `--reload`。示例选择 Uvicorn 单进程，先保证正确性再按负载扩容；不为学习项目强行叠加 Gunicorn。依赖为运行环境验证过的直接版本，定期升级并运行回归测试。

## 2. HTTPS

这里选择 Caddy 统一处理反向代理和证书，不需要同时叠加 Nginx。准备自己的域名，将 A/AAAA 记录指向服务器，开放 80/443，设置 `.env` 中的 `DOMAIN=api.your-domain.com`。

```bash
docker compose --profile https up --build -d
```

Caddy 会向 `api:8000` 转发。API 的 8001 只绑定宿主机回环地址，数据库和 Redis 不发布端口。公网不应绕过代理直接暴露 API；Uvicorn 的转发头信任配置依赖这个隔离前提。证书签发需要真实 DNS、网络和域名，localhost 不等同于获得公网信任证书。

当前没有域名或服务器时完成到本地 Compose 即可，不能把“提供配置”当成“已经公网部署”。

## 3. 迁移与升级

```bash
docker compose build
docker compose run --rm migrate
docker compose up -d api
```

上线前备份数据库。给非空表新增必填列时，分阶段处理：先允许空→回填→验证→改为非空。`--autogenerate` 结果必须人工看过；不会可靠识别所有重命名和约束变化。`stamp` 只记录版本，不能替代迁移执行。

在生产库随意 `downgrade` 可能删列、丢数据。先测试回退方案；复杂变更优先采用兼容升级和修复迁移。

## 4. 日志、排错

```bash
docker compose logs -f --tail=100 api
```

应用输出 JSON 日志，包含请求编号、路径、状态、耗时，不输出密码/Token/请求体。响应头 `X-Request-ID` 可用于关联日志；未知错误返回通用500与请求编号。Redis 断线会记录降级日志。容器日志应配置宿主机轮转或集中采集，避免磁盘被占满。

- API 不起：先看配置校验、迁移和导入错误。
- 404：核对方法和路径；资源可能不存在。
- 405：路径支持其他方法，但不支持本次方法。
- 422：核对 JSON 语法、字段类型、范围和空值。
- 401：Token 缺失、无效、过期或已撤销。
- 403：身份有效但无操作权限。
- 502/504：外部服务异常/超时。

## 5. 数据备份

```bash
mkdir -p backups
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB"' > backups/database.sql
```

备份含用户资料与密码哈希，应受访问控制，不能提交 Git。定期把备份复制到独立介质，并在独立空数据库演练恢复。删除 Compose 容器通常不删除命名卷，`docker compose down -v` 会删除数据库卷，不能作为日常重启命令。

## 6. 上线真实平台前

补上业务需要的角色/组织/资源可见性、登录与注册限流、密码恢复与邮箱验证、审计、容量限制、持续监控和恢复演练。当前用户邮箱公开查询是学习阶段行为，真实平台应改为本人或管理员可见。没有实现的能力不要在简历中写成“生产高可用”。
